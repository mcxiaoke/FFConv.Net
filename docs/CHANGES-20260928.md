# 变更记录 2026-09-28 (同基名多容器文件命名区分与批内冲突报告)

> 类型：命名能力补齐 + 跳过原因可解释性

## 背景

用户反馈：把含 `Big_Buck_Bunny_{1080_10s_5MB,720_10s_2MB}.{mkv,mp4,webm}` 的目录批量转码时，
13 个文件里 4 个被跳过（`destination_exists`），且日志只给出**源文件路径**，
看不出到底哪个目标挡住了自己、更看不出是本批自撞还是旧文件占位。

根因：同一基名、不同容器的文件在默认后缀 `_{preset}`（不含源扩展名）下映射到同一个目标名，
枚举顺序里先到的 `.mkv` 产出成功，后到的 `.mp4` / `.webm` 就撞名了。

## 改动

### `{srcExt}` 系列模板变量（补齐稳定区分维）

- **`FfmpegPlan.CreateDstBaseName`**：新增 `{srcExt}`（`.mkv`）、`{srcExtBare}`（`mkv`）、
  `{srcStem}`、`{srcName}` 四个源文件派生变量。
  - 为什么不用既有变量：`{srcVideoCodec}` 在同容器装同一 codec 时失效；
    `{srcFormat}` 也不可靠——实测 `.mkv` 与 `.mp4` 可能同为 `mov,mp4,m4a,3gp,3g2,mj2`
    （mkv 扩展名的实为 mp4 容器），只有**源扩展名**能稳定区分。
  - 单个用户可用 `--suffix "_{preset}{srcExt}"` 解决全部撞名。

### 批内冲突的识别与报告（不再与旧文件混淆）

- **`FfmpegTask.RefineDestinationConflict`**（新增，core 共享）：把 `destination_exists`
  细化为 `destination_conflict_in_batch` 并记录占用者。
  - 两种原因对应完全不同的动作：旧文件 → 清理或勾选覆盖；本批自撞 → 改命名模板。
  - 放在 core 供 GUI 与 CLI 共用——两边编排模型不同（GUI 逐个 prepare+执行，
    CLI 先全部 prepare 再逐个执行），判定语义必须一致。
  - 兼容运行时跳过的 carrier 差异（`FfmpegRun` 只置 `DstExists`、不写 `SkipReason`）。
  - 大小写不敏感（Windows 路径仅大小写不同也会互相覆盖）；同文件重复扫描时不自我报告。
- **`TranscodeEntry`**：新增 `SkipReason.DestinationConflictInBatch` 与 `ConflictedWithSource`。
- **`FfmpegTask.BuildCliTask`**：目标路径改为在存在性判定**之前**落到 `entry`，
  否则跳过路径只有源路径可报；顺带补上原先漏设的 `DstExistsPath`（同目录冲突分支）。
- **`TranscodeSession` / CLI**：维护批次内「输出路径 → 产出者」映射，
  在 prepare 与执行两处调用共享判定；日志改为**统一给出「源 → 目标」双路径**。
- **`SessionReport`**：统计块新增**跳过清单**（原因 + 目标路径 + 占用者）。
  跳过的文件不在产物里，此前只能逐行翻日志才能知道"哪些没产出、为什么"。

### 文档

- **`presets/default.yaml`**：模板变量表补充新变量与使用说明。
- **`CliOptions`**：`suffix` 说明补充 `_{preset}{srcExt}` 用法。
- **`AboutForm.UsageTips`**：新增第六节"同基名的多容器文件"。

## 改动

### P0-2 `--video-copy` 与缩放/变速/帧率叠加生成必然失败的命令

- **`FfmpegBuild.BuildFilterArgs`**：在组装滤镜前增加流复制短路——当 `UserArgs.VideoCodec == "copy"` 或 `VideoCopy == true` 时直接返回空列表。
  - 视频侧：ffmpeg 对 `-c:v copy` + `-vf` 会直接报 `Filtering and streamcopy cannot be used together`；旧实现只清空了 `preset.Filters`，未清 `Dimension`/`Speed`/`Framerate`，导致这些组合必然失败。
  - 音频侧：一并跳过 `atempo`，避免"音频变速 + 视频原样复制"造成的音画不同步。

### P1-1 AMD 显卡被误判为 `other`

- **`Gpu.NormalizeVendor`**：补充 `radeon` 子串与独立 `amd` 词元识别（`RxAmdWord`）。
  - WMI 最常见形态 `AMD Radeon RX 6800 XT` 此前落入 `other`，导致 AMF 硬编与 swdec 链路整体丢失、静默退化为纯 CPU 软编。
  - 保持 `intel` 判定在前、`ati` 用词元匹配，避免 `Intel Corporation`（含 `ati` 子串）被误判。

### P1-2 单个坏预设导致全部预设加载失败

- **`FFmpegPresets.Init`**：逐个预设 try/catch，坏预设跳过并记录；新增 `LoadWarnings` 暴露加载期告警。
- **`FFmpegPresets.FromFields`**：数值字段改用宽容读取（`NumField` / `NormalizeBitrateField`），非法取值回退默认值 + 告警，不再抛 `FormatException`。移除一处无用局部变量。
- **`MainForm.StartupDiagnostics`**：把 `FFmpegPresets.LoadWarnings` 写入启动日志（Warn 级），使被跳过的预设与降级字段可见。

### P1-3 4 个 `[GeneratedRegex]` 的 `\\s` 过度转义
