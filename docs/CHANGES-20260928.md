## 改动

### P0-1 「使用说明」窗口的关闭按钮被完全遮挡

- **`AboutForm`**：关闭按钮由"直接 Add 到窗体右下角"改为放进 `Dock = Bottom` 的独立 `footer` 面板。
  - 旧实现里 `TabControl` 用 `Dock = Fill` 覆盖整个客户区，而 WinForms 的 z-order 规则是「后添加的位于顶层」、`Controls[0]` 才最顶层，因此按钮被完整盖住。实测 `GetChildAtPoint(按钮中心)` 命中的是 `aboutTabs`，运行期不可见也点不到。
  - 用 Dock 分区隔开后两者区域不再重叠，从根本上消除遮挡。
  - 同时把按钮接入 `AcceptButton` / `CancelButton`，使 Enter 与 Esc 都能关闭窗口（此前两者均无效）。

### P2-1 `ListView` 列宽不随 DPI 缩放

- **`AboutForm`**：新增 `ScaleListColumns`，在 `Shown`（此时 `DeviceDpi` 已确定）与 `DpiChanged` 时按 DPI 换算列宽，用 `ColumnHeader.Tag` 记住 96 DPI 设计基准值，避免重复触发时累计放大。
  - `ColumnHeader.Width` 属于"集合内的数值属性"，`AutoScaleDimensions` 不会缩放它；构造期 `DeviceDpi` 也仍是默认 96。实测 150% DPI 下列宽保持 96 DPI 原值，字体已放大 → 长说明文本被截成省略号。
  - 「说明」列改用 `-2` 自适应标记，缩放函数对负值直接跳过，保留其自适应能力。
  - 「取值」列内容都很短（最长 `bps / 3M / 800k`），由 150 收窄至 110，把余量让给「说明」列。
  - 窗口 `ClientSize` 由 860×620 调整为 1140×660，使「说明」列自适应后的总宽（实测 1650px @150%）能放进视口（1672px），消除横向滚动条。

### P1-5 `ParamsFlowForm` 构造期 DPI 基准缺失

- **`ParamsFlowForm`**：把 `AutoScaleMode` / `AutoScaleDimensions` 从构造函数末尾移到最前（在任何 `Scale()` 调用之前）。
  - `Scale()` 依赖 `DeviceDpi`，而构造期控件尚无父窗体句柄、`DeviceDpi` 返回 96，导致 `BuildHeader` / `BuildFooter` 首次算出的尺寸都是 96 DPI 值；`Shown` 时会重算兜住，但属时序脆弱。
  - `AboutForm` 同样调整为构造函数首行设置基准。

### P2-2 最小尺寸下日志区高度塌陷为 0

- **`MainForm`**：
  - `MinimumSize` 高度由 640 调整为 700。实测（150% DPI）逻辑高 <700 时进度行/进度条会与日志框重叠；700 起 `logBox` 高度稳定在 148px 且互不重叠。
  - `logBox` 增加 `MinimumSize = new Size(0, 100)` 高度下限，避免极端缩放下日志区被压成 0 高（用户完全看不到实时输出）。

## 测试

- 新增 `AboutForm_ListViewColumns_AreScaledForDpi`：断言固定列按 DPI 换算、「说明」列保留自适应能力。

## 改动

### P2-5 「详细日志」开关未作用于 core 日志过滤

- **`TranscodeSession`**：新增 `verboseLog` 构造参数，`ForwardCoreLog` 改用 `FfmpegLogFilter.Apply(line, keepEverything: verboseLog)`。
  - 旧行为只调用 `ShouldKeep`，从不读取该开关：core 在 Debug 下虽切到 `repeat+level+info` 产生大量 stderr，但全部被过滤并计入 `SuppressedLines`，用户勾选后几乎看不到额外输出，而统计块却提示"勾选「详细日志」可全部显示"——提示与事实自相矛盾。
  - 新增 `ForwardCoreLogForTest` 内部接缝与 `InternalsVisibleTo`，使该行为可在不启动真实 ffmpeg 的前提下被断言。
- **`MainForm`**：构造会话时传入 `verboseLog: opts.Debug`。

### P2-8 取消/全部失败路径的状态文案

- **`MainForm.FinishRun`**：取消（`WasCancelled`）改为独立分支，不再把进度条刷满到 100% 后同时显示"已取消"；新增"全部失败"状态，避免 `Success=0 && Failed>0` 时状态栏显示"已完成"、与日志汇总"失败 N"冲突。

### P2-3 `hwaccel` 下拉语义收敛

- **`MainForm`**：下拉由 9 项收敛为 `auto / cuda / qsv / amf / d3d`。
  - `d3d11va / d3d12va / dxva2` 被 core 归一为同一层（`HwDetect.HwaccelAliases`），列四项会让用户误以为有区别；
  - 移除 `cpu`：它与 `auto` 在候选链中完全等价，并非"强制软解"（软解的正规入口是「解码模式 = cpu」，两者语义重叠）；
  - 说明同时写入 `ToolTip` 与 `AccessibleDescription`（后者让屏幕阅读器可读，且可被自动化断言）。

### P1-4 文件对话框名单与扫描器白名单漂移

- **`MainForm`**：新增 `BuildMediaFilter()`，由 `Helper.VideoFormats` + `Helper.AudioFormats` 动态生成过滤器，替换原先手写的扩展名清单。
  - 原清单多写了 `.m2ts / .mpeg / .opus / .ogg`，用户能选中却被 `FfmpegScan` 静默丢弃，最终只看到"没有找到可处理的媒体文件"，无从判断真实原因。

### P2-9 进度条「瞬时刷新」边界保护

- **`MainForm.SetProgressInstant`**：增加 `Maximum <= Minimum` 前置返回，避免零区间时 `v + 1` 越出 `Value` 合法范围抛 `ArgumentException`。

### P3-5 ffargs 含分隔符取值的可解释提示

- **`FfargsValidator`**：`key=value` 解析失败的提示区分首段与残留段；残留段明确提示"疑似前一个取值的分隔符残留（值里不能含 `,` 或 `;`）"。
  - 说明：解析按 `,`/`;` 切分，因此无法在解析后检测取值内的分隔符，只能在此处给出可执行的诊断信息。

## 改动

### P0-2 `--video-copy` 与缩放/变速/帧率叠加生成必然失败的命令

- **`FfmpegBuild.BuildFilterArgs`**：在组装滤镜前增加流复制短路——当 `UserArgs.VideoCodec == "copy"` 或 `VideoCopy == true` 时直接返回空列表。
  - 视频侧：ffmpeg 对 `-c:v copy` + `-vf` 会直接报 `Filtering and streamcopy cannot be used together`；旧实现只清空了 `preset.Filters`，未清 `Dimension`/`Speed`/`Framerate`，导致这些组合必然失败。
  - 音频侧：一并跳过 `atempo`，避免"音频变速 + 视频原样复制"造成的音画不同步。

### P1-1 AMD 显卡被误判为 `other`

- **`Gpu.NormalizeVendor`**：补充 `radeon` 子串与独立 `amd` 词元识别（`RxAmdWord`）。
  - WMI 最常见形态 `AMD Radeon RX 6800 XT` 此前落入 `other`，导致 AMF 硬编与 swdec 链路整体丢失、静默退化为纯 CPU 软编。
  - 保持 `intel` 判定在前、`ati` 用词元匹配，避免 `Intel Corporation`（含 `ati` 子串）被误判。

### P1-2 单个坏预设导致全部预设加载失败

- **`FFmpegPresets.Init`**：逐个预设 try/catch，坏预设跳过并记录；新增 `LoadWarnings` 暴露加载期告警。
- **`FFmpegPresets.FromFields`**：数值字段改用宽容读取（`NumField` / `NormalizeBitrateField`），非法取值回退默认值 + 告警，不再抛 `FormatException`。移除一处无用局部变量。
- **`MainForm.StartupDiagnostics`**：把 `FFmpegPresets.LoadWarnings` 写入启动日志（Warn 级），使被跳过的预设与降级字段可见。

### P1-3 4 个 `[GeneratedRegex]` 的 `\\s` 过度转义

- **`FfmpegBuild`**：`RxAudioCodec` / `RxAudioBitrate` / `RxMapMetadata` / `RxWhitespace` 的 `\\s`、`\\S` 修正为 `\s`、`\S`（verbatim 字符串中 `\\s` 匹配字面反斜杠）。

### P2-6 日志同步文件名截断长度算错

- **`SessionLogWriter.SyncTo`**：改为显式分段拼接（`ffconv-transcode-<yyyyMMdd-HHmmss>-<guid12>.log`）。旧的 `[..(24 + 6)]` 使长度 32 的前缀+时间戳超出 30，guid 被整体截掉且时间戳被截在中间，同秒同步会互相覆盖。

### P2-7 `-encoders` 解析把 `=` 当作编码器名

- **`HwDetect.RxEncoderLine`**：编码器名首字符约束为字母/数字/下划线，排除表头说明行（` V..... = Video`）。

### P3-1 `CalcLongEdge` 可产出 0 边长

- **`HwAccel.CalcLongEdge`**：输出尺寸钳到最小偶数边长 2，避免生成 `scale=w=2:h=0` 这类非法滤镜。
