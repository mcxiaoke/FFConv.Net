## 修复：底部按钮"没有文字"（两个独立缺陷叠加）

# 变更记录 2026-09-26 (参数面板简化为单行列表 + 保存前全量校验)

> 时间：2026-09-26 10:23 (GMT+8)
> 范围：`ParamsForm.cs` 重写 + 测试基础设施加超时
> 类型：返工（按用户反馈简化）

## 为什么返工

用户实测反馈：面板**行与行重叠**（说明文字被下一行盖住），且设计过于复杂（左侧分组导航 + 两行式行布局）。

## 改动

- **布局简化**：去掉左侧分组导航与搜索分组联动，改为**一张平铺列表**；每行固定「参数名 | 说明 | 输入框」三段式，行高固定 30（逻辑），输入框贴右对齐、说明占中间剩余宽度。不再有按内容自适应高度。
- **底部加「保存」**：点击时**校验全部自定义参数**，任何不合法（非法取值、未知参数、GUI 不支持、ffargs 带单位码率）都阻止保存并在状态行与弹窗列出原因。
- **非法参数不再静默丢弃**：解析器会把非法值排除在解析结果外，此前照此填表会让参数"凭空消失"。现在改为保留原文并自动进入手动编辑模式，提示用户修正；编辑模式下仍有解析错误时不允许退出编辑模式。
- **校验基于参数文本**而非表单控件：手动编辑可能粘进未定义/不支持参数，只查控件会漏掉。
- 回滚了上一轮加的 `CliOption.Group` 分组字段与 `ParamGroups`（不再需要，避免无用代码）。

## 测试基础设施：加超时（重要）

- `Ui.RunInSta` 增加 `Join(timeoutMs)`，默认 240s，并把 STA 线程设为后台线程。
  此前一旦撞上模态框或跨线程窗体操作，`Join()` 会永久等待——实测挂死 10 分钟无任何输出。
  现在这种情况会变成一条明确的 `TimeoutException`，且不阻止测试进程退出。
- 顺带修掉一个真实测试缺陷：测试替身窗体在非 STA 线程构造后跨线程 `Show()`，直接挂死。

## 排查并修复的 DPI 缺陷（截图发现）

**DPI 双重标准导致说明文字整片不可见**：`nameLabel` 的坐标经 AutoScale 缩放（285=190×1.5），而 `ReflowRows` 在 AutoScale **之后**运行，用未缩放的逻辑常量设置 `descLabel` 与输入框——说明 Label 只有 22px 高而字体需要 27px，文字被裁成空白，看起来像"说明没渲染"。
修法：重排一律经 `Scale()` 换算为物理像素，且 `layoutReady` 置位前不介入（避免被 AutoScale 二次缩放）。

## 测试

- `ParamsFormTests` 重写为 30 项：布局回归（行不重叠/子控件不越界/首行可见/header 不重叠/最小尺寸下底部控件可见）、打开即还原、编辑→文本、只读分区、搜索、保存校验、手动编辑。
- 结果：**`dotnet build` 0 错误 0 警告**；**`dotnet test` 376 项全绿**（core 95 + GUI 281）；`smoke-exe.ps1` 冒烟通过。全量耗时约 45 秒（返工前因挂起需 10 分钟以上）。

- **新增 `ParamSerializer.cs`**：参数表 ↔ CLI 文本往返。含引号规则（含空白/前导 `-`/含引号必须加引号；单双引号同时出现则拒绝并提示），保证往返不失真。
- **新增 `ParamTrial.cs`（L1 参数试算）**：复用 `GuiOptions.ToArgvShim` + `FFmpegPresets.CreateFromArgv`，即时给出「预设值 → 你的覆盖 → 最终生效值」。纯计算，不碰文件、不探测硬件；如实标注"具体编码器由硬件层决定"与"峰值码率无覆盖通道"。

- **`CliArgParser.IsValidValue`**：面板即时校验复用解析器的同一套规则，避免"面板说能用、开跑却告警"。

## 排查并修复的两个真实布局缺陷（截图发现，非猜测）

- **header 与 body 重叠**：WinForms 的 Dock 是「后添加的先占位」，header 先添加时 body（Fill）会先占满客户区（Y=0），header 只在 z 序上层覆盖，body 不被下推 —— 表现为分组列表与表单各被吃掉两行，而控件坐标完全正常，极易误判成文字裁切。改为最后添加 header。
- **FlowLayoutPanel 自动滚动**：子控件获得焦点时触发 `ScrollControlIntoView`，实测滚动位置变成 135px，首行 `--preset` 被滚出可视区。在重建与 `Shown` 时强制回到顶部。
