# 变更记录 2026-10-11 (转码期间强制阻止系统睡眠)

> 时间：2026-10-11 15:01 (GMT+8)
> 范围：`src/MediaCli.Transcode/Run/`（新增 `SleepGuard.cs`、`FfmpegRun.cs`）、`src/MediaCli.Transcode.Cli/Program.cs`、`src/MediaCli.Transcode.Gui/TranscodeSession.cs`、`tests/MediaCli.Transcode.Tests/SleepGuardTests.cs`
> 类型：电源管理行为新增（无配置开关，强制生效）

## 重点变更摘要

1. **新增防睡眠守卫 (`Run/SleepGuard.cs`)**：
   - 封装 kernel32 `SetThreadExecutionState`，在持有期间以 `ES_CONTINUOUS | ES_SYSTEM_REQUIRED` 阻止系统进入睡眠。
   - RAII 语义：`Acquire()` / `Dispose()` 配对，`Dispose` 时把调用前的线程状态**原样写回**。
   - 用 `[ThreadStatic] depth` 持有深度兜住嵌套与异常路径：只有最外层真正触碰 API，内层只增减计数，避免内层把外层记录的「上一状态」覆盖成中间值。
   - 用 `DllImport` 而非 `LibraryImport`：后者需开启 `AllowUnsafeBlocks`，与项目现状（`MainForm.FlashWindowEx` 同样用 `DllImport`）保持一致。
   - 边界说明：**只阻止系统睡眠**，不阻止屏幕熄灭；合盖休眠需 `ES_AWAYMODE_REQUIRED` 且需用户放开系统「允许此设备唤醒电脑」，属策略变更，未纳入。
   - 进程被强杀时内核自动清除该进程的 execution state request，不会跨进程残留。

2. **接入转码执行链路 (`Run/FfmpegRun.cs`)**：
   - 在 `ExecuteFFmpeg` 方法首行 `using var sleepGuard = SleepGuard.Acquire();`，即**仅在 ffmpeg 真正存活期间**持有；扫描与硬件探测阶段不持有。
   - 转码开始时输出结构化日志 `[POWER] 已阻止系统睡眠（转码结束 / Ctrl+C / 关闭窗口后自动恢复）`。

3. **CLI 补齐 Ctrl+C 优雅取消 (`Cli/Program.cs`)**：
   - 此前 CLI **完全没有**信号处理，Ctrl+C 直接终结进程，ffmpeg 会变成孤儿进程继续占用 GPU（`RunStatus.Cancelled => return 130` 的约定一直存在却无触发路径）。
   - 新增 `CtrlC` 取消源，静态构造函数注册 `Console.CancelKeyPress`，置 `e.Cancel = true` 阻止 CLR 直接杀进程，转而走 core 取消链路：kill ffmpeg 进程树 → 清理临时文件 → `SleepGuard` 在 finally 归还标志。
   - 执行段传入 `RunOptions { Signal = CtrlC.Token, OnLog }`，core 日志转发至 stderr。
   - `--help` 补充说明：执行期间自动阻止睡眠，Ctrl+C 退出码 130。

4. **GUI 日志白名单补 `[POWER]` (`Gui/TranscodeSession.cs`)**：
   - `ForwardCoreLog` 原只对 `[DONE]`/`[CMD]`/`[PREPARE]` 直通，其余按 ffmpeg 原始输出过滤。
   - `[POWER]` 若走该分支会被判为噪声丢弃，并污染「已隐藏 N 行」统计，故新增直通分支映射到 `SessionLogLevel.Info`。
   - GUI 关窗路径无需改动：`OnFormClosing` → `cts.Cancel()` → `RunOptions.Signal` → `ExecuteFFmpeg` finally，与 CLI 共用同一条归还链路。

5. **修复 `StatusBar_ShowsSystemInfo` 的既有竞态 (`tests/.../MainFormInputTests.cs:73`)**：
   - 原等待条件为状态栏文本含 `"CPU"` 或 `"ffmpeg"`，而初始文案「正在探测机器与 ffmpeg 信息…」**本身就含 `ffmpeg`**，条件立即成立，断言在后台探测写入日志之前执行，用例因此偶发失败。
   - 改为等待唯一可靠的终态信号——日志区出现「硬件环境信息」，超时信息里直接带上当前日志全文便于定位。
   - 探测回调中状态栏与日志为连续赋值，终态到达后状态栏必然已填充，故把原先无效的 `Contains("ffmpeg")` 换成 `Contains("CPU")`，并补 `DoesNotContain("正在探测")` 兜底。
   - 连续 5 次单跑全部通过（每次 7-8s），不再依赖时序侥幸。
