# FFConv UI/UX 改进与优化方案

> 日期：2026-09-25
> 范围：src/MediaCli.Transcode.Gui（FFConv 桌面端）
> 前置：不改变 core 转码语义，不破坏现有功能与自动化测试契约，逐项实证、稳步演进。

---

## 一、现状与设计原则

经过对当前 UI 实现（MainForm.cs、AboutForm.cs、TranscodeSession.cs 等）与运行状态截图的核查，当前界面已具备完整可靠的转码、预览、硬件探测与参数映射能力。但仍存在若干直接影响用户日常使用效率和心理体验的交互痛点。

本次 UI/UX 优化遵循以下原则：
1. **真实有用，杜绝花哨**：聚焦转码工具最高频的输入、进度感知、参数理解与反馈链路；
2. **零破坏，向后兼容**：保留所有现有控件命名（Name）与测试契约，确保既有 294 项单元/布局/输入测试持续全绿；
3. **零外部重依赖**：沿用 WinForms 原生框架，不引入额外臃肿组件库；
4. **DPI 与布局绝对安全**：严格保持 AutoScaleMode.Dpi，严格避免同级控件几何重叠与文字截断。

---

## 二、核心优化方案

### 1. 文件与文件夹直接拖拽支持（P0）
- **问题**：目前只能通过对话框点选或文本框粘贴，不支持文件拖放，严重阻断转码桌面软件的最直觉操作。
- **方案**：
  - 窗体 MainForm 及 inputBox 启用 AllowDrop = true；
  - 处理 DragEnter 校验 DataFormats.FileDrop；
  - 处理 DragDrop 调用 AddInputLines 自动解析路径并去重，同时支持直接拖入到输出目录框。

### 2. 进度信息多维呈现（P0）
- **问题**：单文件转码时进度条右侧仅显示 正在处理 1/1 sample.mp4，不显示当前文件的具体百分比（如 45%）和转码倍速（如 2.8x），长视频转码时用户容易误判为卡死。
- **方案**：
  - 在 MainForm.Flush() 更新 progressLabel 时，组合实时指标：
    - 单文件：正在处理 1/1 [45%] · 2.8x · sample.mp4
    - 多文件：正在处理 2/10 [当前 68%] · 2.8x · sample.mp4
  - 任务结束时无缝切回 完成 X/X 或 预览 X/X，与既有断言完全一致。

### 3. 操作按钮视觉主次与热键绑定（P1）
- **问题**：预览命令、开始转码、取消、清空日志、打开输出目录 5 个按钮平铺，视觉权重相同，缺乏视觉重心。
- **方案**：
  - 「开始转码」设为主操作样式（Primary）：采用更醒目的配色与加粗字体，使用户一眼定位核心动作；
  - 增加无障碍键盘热键（Access Keys）：开始转码(&R)、预览命令(&P)、取消(&C)、清空日志(&L)、打开输出目录(&O)。

### 4. 优化未勾选覆盖时的确认体验（P1）
- **问题**：默认未勾选「覆盖已有」，导致用户每次点击「开始转码」都必须多点一次 Warning 弹窗确认，体验繁琐，容易促使用户盲目勾选覆盖。
- **方案**：
  - 增加智能快速预检：仅在输出目标文件切实已存在且未勾选覆盖时才弹出跳过提示；若均为新文件则直接转码。

### 5. 修复「使用说明」窗口列宽截断（P1）
- **问题**：命令行参数列表的第一列（180px）和第二列（130px）偏窄，别名（如 --video-bitrate (v...）和取值被系统截断为省略号。
- **方案**：
  - 调整列宽配置（第一列调至 240px，第二列调至 160px），使完整别名与取值格式正常显示。

### 6. 长时间转码完成提醒（P2）
- **问题**：后台转码结束时缺乏系统级通知或高亮，挂机转码用户不能及时感知。
- **方案**：
  - 任务完成时调用系统 Win32 FlashWindowEx 闪烁任务栏图标；
  - 可选发出柔和的系统提示音（SystemSounds.Asterisk.Play()）。
