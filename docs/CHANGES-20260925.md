## 新增：桌面 GUI（`src/MediaCli.Transcode.Gui`，mediac-gui）

- **框架**：WinForms / `net8.0-windows`，零额外 NuGet 依赖。
- **功能**：输入（文件/目录，可多行）、preset 下拉、hwaccel 与解码模式选择、输出目录与模式、
  自定义参数输入框、覆盖/严格/详细日志/动漫开关、日志面板（着色 + 自动滚动 + 行数上限）、
  进度条、预览命令 / 开始转码 / 取消 / 清空日志 / 打开输出目录。
- **分层**：`GuiOptions`（UI→core 纯映射）、`FfargsValidator`（ffargs 校验）、
  `TranscodeSession`（串行编排 + 取消，等价于 core 未实现的 Engine 层）、`LogSink`（无锁队列 + 批量刷新）。
  前两者不含 WinForms 类型，可被 xUnit 直接覆盖。
- **可靠性要点**：
  - 预览与真实执行**同路径**（走 `TestMode`），先完成真实硬件分层决策再提前返回，
    故预览命令与执行命令一致；识别 core 的 `"test-mode skip"` 哨兵，避免预览被误报为失败。
  - 日志走 `ConcurrentQueue` + 100ms 定时批量刷新，避免高频 `Invoke` 拖慢转码。
  - 执行整体置于后台线程（core 为同步模型，内部 `WaitForExit`）。
  - 严格串行（core 为同步模型 + 进程内静态缓存，并发会互相污染）。
  - 关窗保护：任务运行中先取消并等待进程退出，避免 ffmpeg 变孤儿进程。
  - 启动诊断：显示实际使用的 ffmpeg/ffprobe 路径、版本、GPU、可用硬件层。

# 变更记录（第二轮）：GUI 界面改造

> 时间：2026-09-25 16:05 (GMT+8)
> 范围：按 7 项需求重排界面、自定义参数对齐 mediac CLI、日志与统计增强

## 界面重排

- 分组顺序改为 **输入 → 输出 → 参数 → 操作 → 日志**，底部新增状态栏。
- 「解码模式」右侧新增 **「使用说明…」按钮**，打开 `AboutForm`（三个页签：
  预设清单 + 详情、命令行参数总览、使用提示）。
- 参数区的详细说明文字从界面上移除（仅保留一行指引），全部移入使用说明窗口。
- 新增复选框 **「同步日志到输出目录」**。

## 自定义参数改为 mediac CLI 写法

- `GuiOptions.Ffargs` → `CliArgs`，接受 `--video-bitrate 3M --video-quality 23` 形式，
  不再局限于 ffargs。
- 新增 `CliOptions`（参数表单一事实源，同时驱动解析与「使用说明」窗口）与 `CliArgParser`。
- 优先级与 mediac 一致：**CLI 参数 > 界面控件**；覆盖了哪个控件会在日志中说明。
- 不支持的参数（`--jobs`、`--delete-source-files`、`--doit` 等）**明确告警并说明原因**，
  不静默忽略。

## 日志与进度

- 日志改为**自动换行**，不再出现横向滚动条。
- **进度条按文件推进**（如「正在处理 122/200」）；文件内部的百分比与 speed 只写日志，
  按 10% 或 5 秒节流。
- **过滤 ffmpeg 常规输出**，只保留错误与警告。过滤词表是
  `FfmpegRun.ExtractFFmpegError` 的**超集**，避免"界面报失败但日志无原因"。
- 任务结束输出**统计块**：输入/输出目录、处理结果、总耗时、输入/输出大小（含压缩比）、
  日志文件位置、失败文件清单。
- 新增 `SessionLogWriter`：日志始终写临时文件，可选同步一份到输出目录。

## 状态栏

- 显示 **CPU / GPU / ffmpeg 版本 / 可用硬件层**，悬停显示完整适配器清单。
- GPU 只列主适配器并标注数量——实测本机有 3 个适配器，全量列举会把 ffmpeg 版本
  （需求要展示的字段之一）挤出可视区。

## 新增文件

`CliOptions.cs`、`CliArgParser.cs`、`FfmpegLogFilter.cs`、`SessionLogWriter.cs`、
`SessionReport.cs`、`SystemInfoProbe.cs`、`AboutForm.cs`（含 `AboutContent`）。

除 `AboutForm` 外均不含 WinForms 类型，可被 xUnit 直接覆盖。

## 本轮修复的缺陷

| 缺陷 | 说明 |
|---|---|
| 日志文件名同秒碰撞 | 文件名只精确到秒，同秒内第二次运行因文件占用抛 `IOException`；改为带唯一后缀 |
| 日志文件独占打开 | 转码中无法用编辑器查看；改为允许共享读 |
| 空白行入库 | `"   \n  "` 被写成两行带时间戳的空行 |
| `--speed 0` 被拒 | 0 是 mediac 文档化的「不变速」取值（也是 CLI 默认值），应放行 |
| 短别名大小写 | mediac 中 `-o`=output 与 `-O`=override、`-e`=extensions 与 `-E`=exclude 刻意区分；查表若忽略大小写会互相覆盖 |
| 版本串压缩过度 | 原规则只留前两段，会破坏 git-describe 形态（`n-126733-g1a2b3c`）；改为只裁末尾厂商域名段 |
| 预览显示「完成 0/1」 | 预览不产出文件，`Processed` 恒为 0，读起来像失败；改为「预览 1/1」 |
| 截图时机 | 状态栏探测是异步的，截图抓早只会拍到「正在探测…」占位文本 |
